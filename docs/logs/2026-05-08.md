## 罠 / 学び (今 session 追加)

- **Capacitor APK build は `npm run cap:sync` 必須**: vite default は `base:"/ev-manager/"` のため `npm run build` だと APK 用に不適切。`build:native` で `--base=./` 上書きが必要
- **白画面 = JS 読み込み失敗の合図**: WebView の `file://` 配下に絶対パス参照があると 404、症状は素 React 側が一切動かない (boot console.log すら出ない)
- **lazy import + ErrorBoundary は症状を変えない場面もある**: v5.2.1 で外側を lazy 化しても html 自体が assets を取れない以上、JS 評価まで届かない (「症状 ≠ 根因」の好例)
- **release-apk.sh のような ship pipeline には pre-flight check を仕込む**: 同じ operator 過失を 2 度繰り返さない harness ガード化 (Daily Demand-Anchored の incident anchor から同 day 改善エピソードに昇格)
- **@capacitor-community/sqlite v7 + Capacitor 7 系 pin**: v8 系は Cap 8 要求、Cap 7 では v7.x で固定する

### P3.1 Pro Bridge Round 1: 元案は再設計レベルで却下
GPT-5.5 Pro Bridge に「歩行包含 P3.1 設計」の事前 dissent を要請 (5 軸 / 8 件以上 mandatory)。結果:

- **verdict**: GO_with_changes (confidence 0.78)
- **dissent points**: 13 件 / **must_change_before_implement**: 8 件

主要な must_change:
1. **schema 分離 (id 1, 3, 4)**: AutoTrip 共通でも永続先を `tripLog` (全 mode) + `driveLog` (car-only projection) に分離。memo に mode 埋め込みは migration debt。
2. **mode を first-class column に (id 12)**: SQLite + Sheets で mode / modeSource (manual/heuristic/unknown) / modeConfidence を構造化。memo string ではダメ。
3. **mode 別 confirm policy (id 11)**: 全 trip pending → Confirm は徒歩包含でスケールしない。car=要確認 / non-car=auto-log or batch review に分離。
4. **mode 別閾値 (id 13)**: 100m/60s 共通は車起源、歩行で意味変。
5. **mode confidence 必須 (id 7)**: avg_speed のみは誤判定深刻 (渋滞車→walk、自転車→vehicle)。低 confidence は `unknown` default。
6. **privacy threat model 格上げ (id 9)**: car-only → all-mode で sensitive place masking、retention、明示 toggle 必要。

**Opus blind spot (Pro Bridge メタ分析)**:
- continuity bias で「既存 AutoTrip を少し一般化すれば」と最小差分を選びがち
- v5.2.2 復旧直後の成功体験で schema / product boundary 再設計を避ける
- 「ユーザーが訂正できる」を robustness と勘違い
- community plugin 制約 (AR 不可) ばかり考えて mode の **governance** が後回し
